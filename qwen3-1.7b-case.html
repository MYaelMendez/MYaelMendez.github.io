01 · THE MEASUREMENT, NOT A SPEC SHEET

This is not a recommendation from a blog. A real 5-step NF4 QLoRA ran on this node: Qwen/Qwen3-0.6B, r=16 all-linear, gradient checkpointing, paged 8-bit Adam. Peak allocated 1.66 GiB, 10,092,544 trainable parameters, loss 14.2 → 11.824. The estimator was then calibrated by that measurement — its first version understated VRAM by ~0.4 GiB and would have lied about the 4B case.

03 · WHY THIS ONE

Headroom is the product. 1.99 GiB left means seq length or batch can grow without an OOM. The 3B class leaves only 0.81 GiB — it fits, but it cannot move.

License matches the estate. Apache 2.0 — same regime as the rest of the sovereign stack. Llama-3.2-3B is gated; Gemma is gated.

The corpus is short and structured. Receipts, governed verbs, custody rules. This is exactly where a tuned small model beats a prompted larger one — the task is format and boundary, not world knowledge.

GGUF stays untouched. Train the safetensors base, emit an adapter, apply it at serve time. The deployed GGUF remains byte-identical and hashable. No overwrite, no drift.

04 · WHAT IS NOT TRUE YET

A 5-step loss curve is proof of pipeline, not of quality. A real fine-tune still needs a corpus derived from on-disk receipts with source_sha256 on every record, a disjoint held-out set, and the base model scored first — an improvement claim without a base score is unprovable.

The live llama-server holds 2915 MiB; unload it before a 3B run. The 1.7B needs the same treatment at seq 512. No trained 1.7B adapter exists yet — this page makes the case, not the claim.
