>_PrivateClientLAB · æQR

A QR is an address, not permission.

One discovery layer across many resources, without making every resource public. Integrity is proven by decoding the artifact back. Authority stays with the human.

scan→resolve→verify→request authority→act

Now on every card

Every Private Client card carries an æQR in its corner. People who scan it land on the receipt with a word check; agents get an ae.manifest with authority set to human only.

What it is · what it isn't

It is

A registry of stable resource IDs → canonical routes + scope. A produce-and-verify gate with two real decoders. A deterministic audit → snapshot → compare → repair queue. An explicit, default-deny authority model.

It isn't

A permission system. A renderer that trusts its own bytes. A claim that a fix landed. An implicit grant from scanning. A category placeholder pretending to be resolution.

The two load-bearing rules

1
A QR that has not been decoded back is not a QR. It is a picture of one.

The gate decodes through two independent decoders. The rune magic æ: encodes fine and fails on scan, so transport magic is ASCII (ae:) and the æ identity lives in the payload.

2
Scanning never grants execution.

resolve, read and verify are open. publish, execute and merge need an explicit, scoped capability. Planning a repair ("ready") is not proving it ("verified").

The pieces · ae/

envelope.pytyped transport ae:1:<type>:<b64url(json)>, 8 types
supervision.pyspec → render → supervise → receipt or refuse; 9 measurable checks; cv2 and pyzbar must agree
registry.pystable IDs → canonical routes + scope (public, local, private, hybrid)
orchard.pyaudit → snapshot → compare → repair queue; planning ≠ verification
authority.pyscanning never grants execution; gated actions need a capability
cli.pyone command surface

Use

aeqr registry --category threejs_scenes
aeqr resolve html-surfaces-teologia-index
# produce a QR only if it decodes back through two real decoders
python -m ae.supervision produce secret '{"name":"K"}' --out k.png
python -m ae.supervision selftest      # proves it REFUSES the rune class
aeqr authority publish --id teologia-index   # denied
aeqr authority read --id teologia-index      # allowed
