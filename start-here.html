The rest of this site assumes you already live here. This page does not. It tells you what open source is, how to actually learn it, and where to start inside this estate — in small steps you can run today.

what open source is

Open source means the source code is public: you can read it, run it, change it, and share your changes. Nobody has to ask permission to look. The licence (a file called LICENSE) says what you may do — most of the projects here are MIT, which means "use it, change it, keep the notice".

That is the whole idea. Everything else — forks, pull requests, issues, releases — is just a workflow around those four freedoms.

how to learn it — four moves, in order

01read Pick one small project. Read its README first, then its LICENSE, then one source file. Do not start with the biggest one.
02run Install it and run its tests. Tests are the honest documentation: they show you what the code actually does, not what the author remembers.
03change Break one thing on purpose, then fix it. Change a message, a default, a colour. Small diff, real understanding.
04contribute Open an issue before a pull request. Describe what you saw, what you expected, and how to repeat it. Maintainers answer reproductions.

where to start here

This estate keeps its smallest instruments as separate repositories, each with its own tests. That makes them good first reads.

the smallest useful step

Clone tinycuda, run pip install -e ., then run its test suite. When the tests pass you have read a real open-source project end to end — about 22 tests worth. That is the whole threshold.

what this site will not tell you

It will not tell you that any of this is production-ready, or that a robot moved. Every number here is a simulation trace. The honest page is the film is an instrument — it lists what is measured and what is not true.
